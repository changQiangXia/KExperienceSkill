# 提交组合、Shakeup 对冲与收官

> 目标：让"选哪个提交"成为有依据的决策，而不是最后一分钟的赌博。

## 1. Shakeup 的数学

- public/private 是同一测试集的两个子样本；子样本越小，排名噪声越大。
- 典型信号：公榜高私榜崩（区域 2/6）、CV 可信者私榜反弹（区域 3/4/5）——S3E22 的 7 区域散点。
- 当榜上分带宽度接近 CV 折间方差或提交差异（如 26.38–26.41、大量 0.25），公榜微差没有信息量。

**动作**：

| 私榜风险 | 提交策略 |
| --- | --- |
| 低（CV-LB 相关已证明，测试足够大） | 按 CV 选 1 个最强提交即可 |
| 中（公榜小/分布略偏） | 2–3 个多样提交对冲（不同模型族/不同后处理） |
| 高（公榜小 + 明显 shakeup 历史） | 组合包含"CV 最强"与"稳健/保守"两类，避免全部押公榜最优 |

## 2. 提交预算分配（假设 N 次提交）

```text
开赛 1–2 次：验证格式 + 拿真实锚点（哪怕是 baseline）
中期 60%：对照实验（每次只测一个改动）
预留 20–30%：最终候选与对冲（不要全部烧在探榜/随机种子上）
最后 1 次：收官冻结后的最终选择
```

- 探榜是测量：写清假设与预期；不要用随机种子探榜。
- 如果规则允许"选提交"（select submission），按 OOF 选，不按 LB 选。
- 记录每次提交的模型版本/后处理/时间，避免最后无法复现。

## 3. 组合构建（最大化私榜期望排名）

1. 候选池：CV 前 3–5 个提交（不同模型族或后处理）；
2. 相关性：候选之间 LB/CV 的相关性越低，对冲效果越好；
3. 风险分层：至少 1 个"保守"候选（少后处理、校准弱、对 public 依赖低）；
4. 选择：CV-LB 相关性已证明 → 取 CV 最优；未证明 → 取"CV 最优 + 保守"组合，按剩余槽位分配。

## 4. 收官 48 小时协议

- 不再引入新方法/新数据；只做选择、复现与格式；
- 重跑一次最终训练/推理链路，确认与候选提交一致；
- 跑 `scripts/submission_guard.py`（列顺序/行数/NaN/ID 集合）；
- 确认提交状态为 Submitted 且有凭证；API key/凭证不入库；
- 冻结：写下最终选择理由与未选提交原因。

## 5. 合法与违规边界

- 允许（视规则）：公开讨论区信息、官方允许的外部数据、结构探针、fallback/selection 规则；
- 禁止：泄漏标签、私有数据、违反共享规则的代码/数据、钻平台漏洞（如 sample_submission 套利那类导致重算/换测试集的玩法）；
- 不确定时发帖问主办方；把回复存档进实验台账。
