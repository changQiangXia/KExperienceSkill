# 改进方案生成协议（Improvement Plan Protocol）

> 目标：把"新比赛 + 264 场经验"变成**有力、准确、科学**的改进方案——每个主张有机制、有类比证据、有可证伪实验、有成本与风险。
> 适用：人类与 agent 协作；agent 单独执行时按本协议产出计划，再按 `score-gain-ladder.md` 执行与记账。

## 0. 铁律

1. **不得编造**：所有数字/结论必须来自本场比赛的实测或经验库中的具体场次（注明 slug/topic）；没有证据就写"假设"。
2. **可证伪**：每条改进必须给出"什么结果会推翻它"（kill 标准）。
3. **结构优先**：类比按任务/指标/数据切分/评测约束匹配，不按表面领域匹配（"足球"和"股票"都可能是时序排名问题）。
4. **一次一个变量**：实验设计必须能归因；不能在同一个实验里换数据+换模型+换后处理。
5. **规则优先**：任何数据/探榜/外部资源动作先确认规则；不合规的改进直接淘汰。

## 阶段 1：建立事实底座（Competition Card）

先填一张卡（不写方案）：

```text
任务类型：分类/回归/排序/检索/生成/检测/分割/计数/对局/优化/评审
指标与实现：全名 + 数学结构 + 官方实现链接 + 平均/阈值/容差口径
数据：规模、字段、实体键、时间键、来源、训练/测试切分方式
评测约束：public/private 比例、提交次数、代码赛/notebook、时限/算力/预算
平台与规则：外部数据、共享政策、模型/API 限制、截止时间线
可比经验：case_search 找到的候选 slug（3–7 个）
当前状态：是否已有 metric-correct baseline？CV-LB 相关性？
```

## 阶段 2：经验检索（Retrieval）

1. 用 `scripts/case_search.py` 按 metric/tag/关键词检索 `assets/case_index.csv`；
2. 从命中里选 **3–5 个结构最接近**的场次（同指标族、同数据切分、同评测约束优先）；
3. 读它们的 `analysis/deep/<slug>.md`（在 KStarter 仓库）与 `references/experience-book.md` 对应章节；
4. 抽取**机制**，不是参数：为什么有效、在什么条件下失效、反例在哪个场次；
5. 把每条候选经验写成：

```text
经验：(来源 slug)
机制：
本场结构相似点：
预期作用对象（分数由谁决定）：
反例/失效条件：
证据等级：官方 / 图证 / 原文数字 / 自述 / 矛盾
```

## 阶段 3：生成假设（Hypotheses）

产出 **3–7 条**候选假设。每条必须包含：

| 字段 | 要求 |
| --- | --- |
| 假设 | 一句话：做什么，期望影响哪个分数来源 |
| 机制 | 第一性解释（为什么会影响指标） |
| 类比证据 | 1–3 个 slug + 关键数字 |
| 证伪实验 | 同折 OOF 的具体对照（A/B，一次一个变量） |
| 期望收益 | 量级（0.001 / 0.01 / 0.1）+ 依据 |
| 成本 | 小时/算力/提交次数 |
| 风险 | 私榜风险、合规风险、过拟合风险 |
| Kill 标准 | 什么结果出现就放弃 |

**假设来源清单**（按优先级）：

1. 验证/指标口径修正（最大且最便宜）；
2. 指标结构后处理（中位数/排序/阈值/容差）；
3. 数据结构红利（实体/重复/生成痕迹/OOD/原数据）；
4. 模型族与表示（域内预训练、embedding+GBDT、度量学习、身份任务）；
5. 集成/融合（多样性与 OOF 增量）；
6. 训练策略（课程、伪标、蒸馏、分层 LR、长尾）；
7. 提交策略（组合对冲、选择规则）。

## 阶段 4：排序与实验设计

1. 按 **预期收益 / 成本** 排序，先做前 3 条；
2. 每条实验：固定 fold、固定 metric 实现、一次只改一个变量、记录台账；
3. 独立实验可并行（不同假设互不依赖时）；
4. 每轮结束更新：分数模型、已证伪假设、下一轮 3 条；
5. 连续两轮无 OOF 增益 → 回到阶段 1 重新诊断（而不是继续调参）。

## 阶段 5：输出格式（Improvement Plan）

```markdown

## 1. 诊断（事实底座）
- 任务/指标结构：
- 数据切分与已知风险：
- 当前 baseline 与 CV-LB 状态：
- 分数由谁决定 / 噪声地板：

## 2. 类比案例（证据）
- <slug>：机制 + 数字 + 与本场相似点 + 失效条件（证据等级）

## 3. 候选改进（按期望收益排序）
| # | 假设 | 机制 | 类比证据 | 证伪实验 | 期望收益 | 成本 | 风险 | Kill 标准 |

## 4. 执行顺序与并行安排
- 第 1 轮（最高期望）：
- 第 2 轮（依赖第 1 轮结果）：
- 并行轨道：

## 5. 风险与合规
- 私榜风险 / 合规 / 预算：

## 6. 成功判据
- 达到什么指标算成功；否则回退与下一假设：
```

## 阶段 6：Agent 协作协议

当多个 agent 协作时，按角色分工并强制交接物：

| 角色 | 职责 | 交接物 |
| --- | --- | --- |
| Retriever | 检索类比场次与机制 | 经验条目（含 slug/证据等级/失效条件） |
| Validator | 指标实现、fold 设计、CV-LB 判据 | 验证备忘录 + metric 单测 |
| Experimenter | 执行单变量实验 | 台账行（改动/ΔCV/ΔLB/成本） |
| Auditor | 审查证据等级、反例、合规 | 审计意见（通过/降级/否决 + 理由） |
| Scribe | 汇总 Improvement Plan 与复盘 | 计划文档 + 决策记录 |

交接规则：

- 任何实验结论必须附台账行与可复现命令/notebook；
- 任何"提升"必须能指出同折对照；无对照 → 标记为"未验证"；
- Auditor 有权把自述级证据降级为假设；
- 计划中的每个行动都必须有负责人、成本上限与 kill 标准。

## 反模式

- 直接给"上 XGBoost/大模型"式建议（无机制、无类比、无法证伪）；
- 把公共 notebook 的参数当经验（换场失效）；
- 用 LB 结果证明假设（没有同折对照）；
- 一次改多个变量、事后归因；
- 忽略规则与合规，或把不合规红利写进计划。
