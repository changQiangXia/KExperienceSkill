# 验证设计：让 CV 成为可用的测量仪

> 规则：CV 与 LB 不同向时，不允许用模型结论做提交决策；先把测量修好。

## 1. 折选择决策树

```text
有实体键（玩家/患者/用户/设备/酒店/图源）？
├─ 是 → 实体是否整体落在 train 或 test？
│         ├─ 是 → GroupKFold(实体) 为诚实口径；同时记录 KFold 作为"乐观上界"
│         └─ 否 → 先查重复/近重复，再 GroupKFold 防重复实体
├─ 有时间键？
│   ├─ 预测未来 → 时间切分 + purge/embargo；禁随机 KFold
│   └─ 仅时序特征 → 滑动/扩展窗验证
└─ 合成数据？
    ├─ 原数据可得 → 随机目标 z 检验
    ├─ 原数据可用 → 对抗验证后再合并
    └─ 生成痕迹明显 → 检查孪生行/生成顺序/重复倍数
```

## 2. CV↔LB 关系：三种情形与动作

| 情形 | 判据 | 动作 |
| --- | --- | --- |
| LB 与 CV 同分布、样本足够 | CV–LB 秩相关高（多次提交后验证） | 以 CV 选模；LB 做确认 |
| LB 是小样本/分布红利 | CV 样本 ≫ LB（5407 vs 721）；榜上分带极窄 | LB 视为随机变量；限制提交；按 CV + 分布整形 |
| CV 与 LB 完全无关 | 实体/时间泄漏、口径错误、提交格式错误 | 停止调参；先查泄漏、metric 实现、列顺序 |

**操作化**：记录每次提交的（CV, LB），至少 3–5 个点后再判断相关性；相关性未建立前，LB 只用于验证格式与绝对水平。

## 3. 三个便宜的验证实验

1. **随机目标检验**（合成/生成数据）：目标打乱 100 次训练同款模型，原目标 CV 落在随机分布 ±2σ 内 → 原数据无信号，收益要转向生成痕迹与稳健集成（S5E9 z=-0.83）。
2. **对抗验证**（原数据/外部数据）：train vs test 二分类 AUC ≈0.5 才可安全合并；合并后再用 CV 证明增益（S3E18）。
3. **实体/重复审计**：实体块切分 + 重复率 + 近重复图/文本；重复行进入验证会直接虚高 CV（GroupKFold 分数更低但更真实）。

## 4. 分组 CV 与 LB 冲突时

- 先问"数据是怎么切分的"：若实体整体落在一侧，GroupKFold 才是诚实的；KFold 的低分不是"更差"，而是把泄漏还回来了。
- 用 LB 做 A/B：如果 GroupKFold 选出的提交在 LB 上同向更好，说明 LB 与真实泛化一致；反之登记为悬案，改用对冲提交。
- 不要因为"分组后分数难看"就退回归随机切分——那是用泄漏买 CV。

## 5. 探榜纪律（合法前提下）

- 探榜是测量，不是得分手段：每次探榜要写清"测什么假设、预期什么模式、花掉几次提交"。
- 优先结构化探针（常数、极端值、单位变换）而不是随机种子探针；后者通常只能测噪声。
- 探榜结果只用来更新 CV-LB 模型；不要用它直接调模型参数。
- 若赛事规则禁止某些探榜/外部数据行为，本步骤直接跳过——规则优先。

## 6. 验证产出物（每场收尾必须齐全）

- 一份 fold 列（保存进训练数据，所有实验共用）；
- 一份官方 metric 实现 + 单元测试；
- 一张提交台账（CV / LB / 提交时间 / 模型版本 / 处理）；
- 一份"CV 可信度"结论：可信 / 有偏（方向）/ 未知，以及对应决策规则。
