# 公开情报差分：抄什么、改什么、不碰什么

> 目标：用最少的读取时间，从公开 notebook/讨论区里找到"能上分的差分"，而不是复制一个公榜过拟合解。

## 1. 读什么（按价值排序）

1. 官方：Overview / Evaluation / FAQ / metric 实现 / 数据字典 / 规则更新帖；
2. 获奖方案与高票 write-up：任务重构、验证方案、失败路径；
3. 高分公开 notebook：只在**有 CV 证明**时参考；
4. 讨论区：数据怪癖、泄漏提醒、shakeup 分析、版本更新；
5. 相似赛的 top 方案：跨场方法直接迁移（如图文检索借 Shopee、细粒度借 FGVC 系列）。

## 2. 差分四问

1. **大家共同做什么？**（饱和区：GBDT 三件套、公开 ensemble、常见 FE）——照做只能保底；
2. **大家都没做什么？**（验证口径、指标结构、后处理、数据审计、失败路径）——这里最容易出增量；
3. **公开方案的分是怎么来的？**（CV 可信？LB 过拟合？数据红利？）——不能解释的来源不抄；
4. **我们有什么独特资产？**（领域知识、算力、数据、工具、时间）——用它构造差异化。

## 3. 执行流程

```text
1. 复现 1–2 个公开 baseline，记录它们的 CV 与验证口径
2. 对照自己的 CV，定位差距来自：验证/数据/模型/后处理 哪一层
3. 只抄"机制"（验证方案、特征思路、后处理结构），不抄"公榜权重"
4. 针对饱和区做差分：换验证口径、换后处理、换数据切分、换集成结构
5. 每个差分做同折对照；无提升则回到第 1 步
```

## 4. 不碰清单

- 无 CV 的高分公开 notebook（大概率过拟合公榜）；
- 标注"leak/exploit"但赛事规则未确认的玩法；
- 私有代码/数据、未公开的团队方案；
- 公开 notebook 的硬编码权重/阈值（换场即失效）；
- 竞赛末期的公开高分方案（可能是公榜钓鱼，且时间不够验证）。

## 5. 引用与合规

- 复用公开代码要注明来源并给出增量；
- 遵守比赛共享规则与信息发布时间限制（部分赛事末期禁止发布公开 notebook）；
- 提交里不出现私有凭证、他人数据或未授权素材。
