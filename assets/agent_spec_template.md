## 1. 目标与验收（可量化）

- 比赛/任务：<slug>，指标：<metric>，当前基线：<CV/LB>
- 本轮目标：<例如"单模 CV ≥ 0.9705"或"迁移 150 个脚本并复现 CV ±0.0003">
- 验收证据：<本地 CV 表 + 折文件哈希 + 日志路径>；**没有同折对照的增益按 0 计**
- kill 标准：<连续 N 轮无改善 / CV 增益 < MDE / 超预算>

## 2. 规则与合规（先填，缺一不开跑）

- [ ] 已读比赛规则/FAQ：是否允许 agent 生成代码、自动化实验、外部 API、外部数据
- [ ] 是否允许自动提交；若允许，谁有提交权限（默认：只有人）
- [ ] 是否需要披露 LLM/agent 使用；需要则记录模型与版本
- [ ] 红旗：自动提交、爬取、评测器探测、泄漏式特征 —— 一律先停下问人

## 3. 数据与泄漏约束

- 折文件：<路径/生成方式/seed>；共享折文件固定，不再重抽
- 目标编码/统计特征：必须嵌套折内（反例：s6e2 的 KFold 外 TE）
- 外部数据/公开代码：列出许可与来源；**公开代码与本地划分不一致 = 潜在泄漏**（rogii 7th 教训）
- 泄漏审计：<每轮产出后由第二个 agent/人做对抗验证或逐列检查>

## 4. 环境与预算

- 运行环境：<沙箱/镜像>，GPU：<型号×数量>，并发：<worker 数>
- 预算硬上限：token <…>｜GPU 小时 <…>｜墙钟 <…>；失败预算 <…>
- 日志与回滚：每轮备份 → 实验 → 验证 → 晋级/还原；产物写 <目录>

## 5. 实验协议

- 台账：`local_leaderboard.md`（每轮追加：配置 / CV / 成本 / 决策）
- 事务门：backup → experiment → validate → promote/restore；**零回归才晋级**
- 在线波动：用差分提交二分定位；技巧在线确认后才合并进 `tricks.md`
- 每轮硬目标：<例如"每个 worker +1.5 分"或"每轮产出 ≥ 3 个可评估候选">

- [ ] 人工复核点：重要提交前必须人工 diff/核对（工具幻觉反例：gemini-3 "谎称改了代码"）
